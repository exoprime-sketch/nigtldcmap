## 3. MAP-002 — 원인은 우측 패널이 아니라 **범례**였다

이전 기록은 "MAP-001 과 같은 원인으로 본다"고 추정했다. 이번에 직접 측정한 결과 그 추정은 틀렸다.

`probe-map-occlusion-v137.mjs` 로 A-024-WB2016-0001 에 닿는 **모든** 화면 좌표의 최상단 요소를 셌다(BUILD-C 이전 상태):

| 폭 | 대상 좌표 수 | 가리는 요소 | 비율 |
|---|---|---|---|
| 1440 | 25 | `cdp-map-legend` | 25 / 25 |
| 1024 | 24 | `cdp-map-legend` | 24 / 24 |
| 958 | 26 | `cdp-map-legend` | 26 / 26 |

우측 `cdp-map-evidence` 는 1440 에서 이 선로를 **한 좌표도** 가리지 않는다. MAP-001 의 폭 조정(769–1099px 대상)이 1440 의 이 결함을 고칠 수 없었던 이유다.

### MAP-001 의 80% 수치에 대한 정정

이전에 기록한 1024 = 80.9%, 958 = 80.4% 는 **데이터를 아직 선택하지 않은 화면**에서 측정한 값이다.
범례는 데이터를 선택해야 나타나고, 데이터 선택은 이용자가 가장 먼저 하는 조작이다.
데이터와 대상을 선택한 실제 상태에서 다시 재면 아래와 같았다.

| 폭 | 이전 기록(빈 지도) | 실제 사용 상태 (수정 전) | 수정 후 |
|---|---|---|---|
| 1440 | 93.6% | 72.7% | 71.9% |
| 1024 | 80.9% | 49.6% | **54.1%** |
| 958 | 80.4% | 45.3% | **50.7%** |
| 768 | 89.7% | **0%** | **70.7%** |
| 390 | — | 2% | **45.4%** |

80% 를 새로운 합격선으로 쓰지 않는다. 이 수치는 진단 지표이며, 합격 판정은 위 2절의 실제 hover·click 결과다.

### 수정한 것

1. **범례에 접기 컨트롤을 추가**했다(`map-legend-toggle-v137`). 기본은 펼침 — 값·발전원으로 색을 칠하는 지도는 범례 없이 읽을 수 없다. 접으면 제목과 토글만 남고 지도가 드러난다. 지도를 패널 위로 올리거나 패널에 `pointer-events:none` 을 걸지 않았고, 범례의 토글·스크롤은 그대로다.
2. 범례 높이 상한을 769px 이상에서 `min(46vh, 380px)`, 768px 이하에서 `40%` 로 낮췄다. 내부 스크롤이 있어 문구·범례 항목이 잘리지 않는다.
3. 769–1099px 의 우측 패널 높이 상한을 65% → 52% 로 낮췄다. 이 패널도 내부 스크롤이며 제목·버튼·범례가 잘리지 않는다.
4. **768px 이하에서 데이터를 선택하면 목록 서랍이 닫힌다.** 그 전에는 서랍이 화면 전체를 덮어 데이터를 고른 직후 지도의 **0%** 만 조작 가능했다. 토글로 언제든 다시 연다.

검사용으로 패널을 닫거나 대상 위치를 바꿔 통과시킨 것이 아니다. 하네스가 기록한 조작(`reachTrail`)은 이용자가 하는 것과 같은 조작이고, 그 기록이 결과에 남는다.

## 4. MAP-003 — 원인은 **지도 계약이 이전 납품의 열 이름을 그대로 복사**한 것

`map-index.json` 의 `tooltipFields` 와 `filters` 는 V1 지도 색인을 그대로 복사하고 있었다.
그 이름들은 이전 납품의 열 이름이고, 최종 납품은 요소마다 열 이름이 다르다.

| 요소 | 계약이 찾던 이름 | 원천이 실제로 쓰는 이름 |
|---|---|---|
| B-048 | `mineral`, `regionName` | `광종`, `소재_행정구역_성` |
| A-023 | `fuelType`, `capacityMw`, `status` | WRI 행은 `primaryFuel`·`mw`, OSM 행은 `fuelType`·`capacityMw` |
| C-025 | `standard`, `technologyField`, `creditingPeriod` | `속성5_등록표준_출처`, `속성6_분류`, `속성17_크레딧기간` |
| A-024 | `voltageKv`, `lengthKm` (자료연도 없음) | 이름은 맞으나 자료연도가 계약에 없었다 |

그래서 `normalizedAttributes["mineral"]` 은 undefined 이고 `normalizedAttributes["광종"]` 에 니켈이 있었다.
팝업에 광종이 없었을 뿐 아니라, 우측 패널의 "값 제공 여부" 가 **원천에 있는 값을 "원천 미제공: 광종 · 지역" 이라고 잘못 진술**하고 있었다.

### 수정한 것

`tools/vietnam_spatial/map_facts_v137.py` 에 요소별 **공개 항목 계약**을 두었다. 각 항목은 공개 키, 한국어 라벨,
그 값을 담을 수 있는 원천 열 이름들(우선순위 순)을 갖는다. 빌드가 **납품된 레코드에 실제로 값이 있는 항목만** 발행하므로
레이어는 원천에 없는 항목을 광고하지 않고, "원천 미제공" 은 원천이 진짜로 비운 항목만 가리킨다.
필터의 값 목록도 이전 납품의 값이 아니라 **이번 납품의 실제 값**에서 만든다.

원천에 없는 값을 만들지 않았고, `normalizedAttributes` 를 무조건 나열하는 우회도 하지 않았다.

| 요소 | 발행되는 항목 |
|---|---|
| A-023 | 발전원 · 설비용량(MW) · 용량구간 · 운영자 · 가동 시작 · OSM 객체 ID |
| B-048 | 광종 · 소재 성·시 · 기후기술 연계 근거 · 좌표 산출근거 |
| C-025 | 등록표준 · 기술분야 · 상태 · 크레딧 기간 · 소재 지역 · 사업자·기관 · 방법론 · 연간 예상감축량 · 원천 식별번호 · 공식 원문 |
| A-024 | 전압 · 확인된 길이 · 선로 상태 · 자료연도 |

C-025 는 §2 가 "사업기간" 이라 부른 항목을 원천이 **크레딧 기간**(속성17)으로만 제공한다. 원천에 없는 사업기간을 만들지 않고 원천의 이름 그대로 표시한다.

부수로 드러나 함께 고친 것:

- **A-023 의 WRI 236개 발전소 이름이 설비용량이었다.** 이 납품의 WRI 행은 속성 열이 용량·연료뿐이고 발전소명은 note 열에 `명칭: Kon Dao` 형태로 들어 있다. 이름 결정이 "첫 번째 속성값" 으로 떨어지면서 236곳이 지도·패널·다운로드에서 `1.0`, `156.0`, `170.0` 으로 표시되고 있었다. 원천이 진술한 이름을 읽도록 고쳤다(다운로드 236행 확인).
- **겹친 선로 4개가 모두 "베트남 송전망" 으로만 표시**되어 구분이 불가능했다. 선 피처에는 name 이 없어 레이어 제목으로 되돌아가고 있었다. 전압·길이로 구분하도록 고쳤다.
- 전압이 숫자여서 문자열 전용 정규화기가 **모든 전압을 버리고** 있었다(`110`→`""`). 선로 제목이 전부 "송전망 구간" 이 된 원인이기도 하다.
- 지도 데이터 선택 안내문의 `을(를)` 자리표시자를 `선택 데이터: <이름>` 으로 바꿨다.

**12 / 12** 가 전 구간 통과했다. 대표 3건은 390·768·958·1024·1440 다섯 폭 전부에서 통과한다.
12개 전수는 1440 에서만 수행했다 — 다른 폭의 나머지 9개는 PENDING 이다.

### 이 전수에서 드러난 것

- **음수 부호가 화면에서 사라지고 있었다.** 공개 문구 정규화기가 앞뒤 구분자를 다듬으면서
  ASCII 하이픈을 함께 지워, `-822,213` 이 `822,213` 으로 표시됐다. 순흡수원인 성이 같은 크기의
  배출원으로 읽히고, 같은 값에 대해 팝업(-822,213)과 우측 패널(822,213)이 서로 달랐다.
  부호 뒤에 숫자가 오면 다듬지 않도록 고치고 회귀 테스트를 추가했다
  (`src/data/visualization/publicFieldPolicyV126.test.ts`).
- **겹친 피처의 선택 목록이 서로 구분되지 않았다.** 선로 4개가 모두 "베트남 송전망"이었고,
  D-018 은 참여국 범위 2개와 활동지점 1개가 모두 같은 사업명이었다. 이제 선로는 전압·길이로,
  사업은 역할(지역 협력사업 / 세부 활동지역)과 지점명으로 구분된다.
- **D-018 의 참여국 범위와 활동지점이 같은 선택키를 공유**하고 있어 서로 다른 대상으로 식별되지
  않았다. 피처마다 고유 키를 준다.

### 하네스가 이 과정에서 더 정확해진 것

- 후보 좌표는 대상이 **그 지점의 최상단 피처**일 때만 채택한다. 단순히 "그 지점에 있다"로 잡으면
  성 경계 픽셀에서 이웃 성이 이기고, Lai Châu 를 겨눈 채 Lào Cai 의 값을 읽게 된다.
- 타일 로드가 아니라 **카메라 정지**를 기다린다. 데이터 선택은 fitBounds 를 시작하고,
  `ready()` 는 그 이징 도중에도 참이다. 12개를 연속 실행했을 때 폴리곤 4개가 실패한 원인이 이것이었다.
- 점 피처는 격자 탐색 전에 **렌더러가 투영한 자기 좌표**를 먼저 시도한다. 12px 격자는 6px 원을
  통째로 건너뛸 수 있다.
- 대상이 군집에 들어 있거나 다른 점 아래 있으면 **그 좌표를 향해 확대**한다. A-023 은 zoom 13 까지
  군집하므로 시작 뷰(5.2)에서는 개별 발전소가 아예 화면에 없다.
- 앱이 겹침 선택 목록을 내놓으면 **그 목록에서 대상을 고른다.** 앱이 추정을 거부한 것을 실패로
