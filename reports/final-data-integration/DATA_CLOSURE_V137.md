## C-016 — 재생에너지 계획용량 (개정 PDP8)

최종 납품은 이 요소를 관측 시트가 아니라 개체 속성 열로 보냈고, 파생이 없어 이전 투영을 그대로
쓰고 있었다(`ENTITY_FORM_NOT_YET_DERIVED`). `tools/vietnam_etl/c016_facts_v137.py` 가 그 파생이다.

원천 817행의 의미별 처분:

| 처분 | 행 | 내용 |
|---|---|---|
| 성·시 계획용량으로 발행 | **639** | 8개 기술 × 63개 성·시 × 2개 기간, 단위 MW |
| 권역(Bắc Bộ 등) 소계 | 84 | 성·시로 배분하지 않고 별도 보존 |
| 전국값·일정·제도 | 57 | 발주기관(MOIT), 계약주체(EVN), 경쟁입찰 원칙, FIT 종료 시점, DPPA 등 |
| 미발행 | 37 | 모두 `NO_NUMERIC_VALUE` — 원천이 그 칸을 비웠거나("약 45" 같은 근사표현) 값이 없다 |

구분해서 유지한 것:

- **기술** — 옥상태양광·집중형 태양광·육상 근해 풍력·바이오매스·폐기물·소수력·양수발전·수력 30~50MW.
  각각 별도 변수이며 서로 더하지 않는다.
- **지역 단위** — 권역 소계와 전국 총계를 성·시로 재배분하지 않는다.
- **기간** — `2025-2030` 과 `2031-2035` 는 같은 계획의 두 기간이며 보간하지 않는다.
- **하한·상한** — 원천이 범위로 준 값(전국 13쌍)은 하한·상한을 각각 유지하고 평균 내지 않는다.
- **계획판본** — 모든 값이 `Quyết định 768/QĐ-TTg (2025-04-15) · 개정 PDP8 Phụ lục II` 를 달고 다닌다.
- **단위 경계** — 계획이 쓰는 이름(개편 전 63개 성)으로 경계에 매핑한다. 원천의 2025년 개편 후 34개
  체계 이름과 P-code 는 기록만 하고 값을 옮기는 데 쓰지 않는다. 미매칭 지역명 0건.

목표용량을 설치용량으로 바꾸지 않았다. 모든 값의 라벨이 "계획용량"이다.

한 가지 오분류를 잡았다: 하한/상한 판정이 설명문에 들어간 `min` 을 그대로 찾고 있어
**Hồ Chí Minh** 의 10개 성·시 목표가 "하한(min)" 변수로 갈라져 있었다. 이제 `하한`/`(min)` 형태만 인식한다.

## D-018 — Adaptation Fund 검증 활동지점

최종 납품은 좌표를 `지점` 한 열에 `"위도,경도 이름 ; 위도,경도 이름"` 형태로 담는다.
이전 투영이 같은 열에서 만들었던 `sourceCoordinateCandidates` 를 새 필드에서 다시 연결했다
(`tools/vietnam_etl/d018_facts_v137.py`). **2라는 숫자를 맞춘 것이 아니라 좌표가 같은지 확인했다.**

| 확인 항목 | 값 |
|---|---|
| 사업 수 | 4 (다국가 2 · 단독국 2) |
| 원천 좌표 총수 | **7** |
| 활동지점으로 판정 | 3 (Young Basin · Tram Chim National Park 주변 · Mekong Delta) |
| 국가 대표점으로 판정 | 4 (Cambodia · Lao · Thailand · Viet Nam) |
| 이전에 검증된 두 지점의 좌표가 최종 원천에 그대로 있는가 | **YES** (16.543095,104.720449 / 10.7177,105.5091) |

라벨이 참여국 이름뿐인 좌표는 국가 대표점이며 시설로 그리지 않는다. Greater Mekong 사업의 4개
좌표가 그것이다. 지도 자산은 그대로 4개 피처(참여국 범위 2 + 검증 활동지점 2)를 유지한다.
검증된 두 지점이 원천에서 사라지면 빌드가 실패한다.

네 개 합계도 최종 원천에서 다시 계산했고 이전 값과 정확히 일치한다:

| 지표 | 값 |
|---|---|
| 사업 건수 | 4건 |
| 승인액 합계 | 23,244,067 USD |
| 집행액 합계 | 10,503,442 USD |
| 베트남 단독사업 승인액 합계 | 11,345,292 USD |

다국가 2건의 승인액은 전체 사업 기준이고 Adaptation Fund 가 베트남 귀속분을 게재하지 않는다.
그래서 단순합과 단독국 합계는 서로 다른 두 수치로 유지하며 하나로 합치지 않는다.

부수로 고친 것: 지도 자산이 사업 속성을 이전 납품의 영문 열 이름(`projectName`, `approvedAmount`,
`sector`, `status`, `implementingEntity`, `sourceUrl`)으로 읽고 있었다. 최종 납품은 같은 값을
`명칭`, `승인금액`, `분야`, `상태`, `실행기관_IE`, `프로젝트_URL` 로 보낸다. 최종 원천으로 투영을
바꾸는 순간 사업 팝업과 우측 상세가 전부 빈칸이 될 상태였다. 또한 참여국 범위 폴리곤과 두 활동지점이
같은 `recordId` 하나를 공유하고 있어 서로 구분되지 않았다 — 피처마다 고유 선택키를 준다.

## B-034 전국 잔여

이전에는 56행을 "전국 계열"로 세기만 하고 발행하지 않았다. 이제 의미별로 처분한다.

| 처분 | 행 |
|---|---|
| 전국 관측으로 발행 | **47** |
| 재수록(alias) | **9** |
| 성·시 값의 전국 지표 재수록(기존 기록) | 126 |
| 미발행 | 1 (`MISSING_VALUE`) |

47건의 내역:

- **연간 시계열 24건** — 산림탄소 총배출 2001…2024년. 각각 실제 데이터 연도를 갖는 연간값이며
  `statisticType=annual`, `year` 가 채워진다.
- **기간값 12건** — 총배출·총흡수·순플럭스의 2001–2024 연평균. `year` 는 비우고 `period=2001-2024`,
  `statisticType=annual-mean` 로 둔다. 원천 `기준연도` 칸의 2025는 자료 추출 시점이므로
  `source_year_label` 로 따로 싣는다. 24년 평균을 2025년 값으로 날짜 찍지 않는다.
- **임계값 차원 11건** — 수관피복률 ≥30/50/75% 의 저장량·밀도·수관면적. 임계값은 별도 차원이며
  지표 ID(`_t30` 등)와 라벨에 모두 남는다.

**재수록 판정 기준**: 대상·지표·값·단위·기간·임계값이 모두 대응할 때만 alias 로 묶는다.
9건은 같은 값을 `지상부 탄소밀도 — 임계값별 — 수관피복률 ≥50%` 와
`산림탄소 임계값별 지상부 탄소밀도 — 50%` 로 두 번 적은 것이고, 단위도 `Mg CO₂e/yr` 와 `Mg CO2e/yr`
로 표기만 다르다. 임계값이 다르면 묶지 않는다.

다운로드에서도 `year` / `period_start` / `period_end` / `period` / `statistic_type` /
`source_year_label` 이 각각 별도 열이다.

**과해석하지 않은 것** — 확인된 사실만 적는다:

| 수치 | 값 |
|---|---|
| 24년 연간 총배출의 평균 | 110,966,746 Mg CO₂e/yr |
| 원천이 임계값 없이 적은 총배출 | 109,607,640 Mg CO₂e/yr |
| 임계값 30% 총배출 | 110,912,381 Mg CO₂e/yr |
| 지도의 63개 성·시 총배출 합계 | 110,912,380 Mg CO₂e/yr |

지도 합계는 **임계값 30% 전국값과 일치**한다(반올림 1 차이). 임계값 없이 적힌 109,607,640 은
연간 시계열의 평균도 아니고 성·시 합계도 아니다. 셋을 같은 수치로 취급하지 않으며, 어느 하나를
"확정된 추세"나 "평균"으로 바꿔 적지 않는다.

## A-023 고유시설 구분

`reports/final-data-integration/a023-identity-v137.json` (재생성:
`node scripts/v137/report-a023-identity-v137.mjs`).

| 항목 | 값 |
|---|---|
| 원천 자료 건수 | **1,963** (WRI 236 · OpenStreetMap 1,727) |
| 좌표가 있어 지도에 표시되는 건수 | 1,889 |
| OSM 객체 ID | 1,727개, 전부 고유 (`node/…`, `way/…`, `relation/…`) |
| WRI 발전소 ID | 236개, 전부 고유 |
| 두 출처가 공유하는 식별체계 | **없음** |
| 확인된 동일시설 쌍 (≤150 m + 발전원 일치 + 용량 2% 이내) | **31** |
| 고유시설 수 하한 | 1,932 |
| 용량이 적힌 건수 | 475 / 1,889 |

거리 기준을 바꿨을 때의 결과도 함께 남긴다(50 m 7쌍 · 150 m 31쌍 · 500 m 50쌍 · 1,000 m 59쌍).
가까이 있으나 발전원이 다르거나 용량을 비교할 수 없는 건은 동일시설로 세지 않았다.

- 공통 ID가 없다는 이유만으로 중복 0을 선언하지 않았다. 근거로 확인 가능한 31쌍을 제시한다.
- OSM 식별정보(object type + ID)를 `OSM 객체 ID` 항목으로 보존한다. 이전에는 `field_33702ec7`
  라는 해시 이름 아래 있어 화면·다운로드 어디에서도 읽을 수 없었다.
- 용량 합계 103,340 MW 를 **국가 총설비용량으로 쓰지 않는다.** 세 건 중 한 건만 용량을 적고 있고,
  확인된 31쌍이 두 번 더해진 수치다.
- 지도 요약의 "총 발전소 N건" 을 "표시 자료 건수 N건" 으로 고쳤다. 자료 건수를 발전소 수라고
  진술하고 있었다. 레이어 안내문도 두 등록부가 섞여 있어 같은 발전소가 두 건으로 실릴 수 있음을 밝힌다.
- 삭제·병합은 하지 않았다. 전체 공개 승인은 그대로다.

부수로 고친 것: **WRI 236개 발전소의 이름이 설비용량이었다.** 이 납품의 WRI 행은 속성 열이 용량·연료
뿐이고 발전소명은 note 열에 `명칭: Kon Dao` 형태로 들어 있는데, 이름 결정이 "첫 번째 속성값"으로
떨어지면서 지도·패널·다운로드에서 `1.0`, `156.0`, `170.0` 으로 표시되고 있었다.
