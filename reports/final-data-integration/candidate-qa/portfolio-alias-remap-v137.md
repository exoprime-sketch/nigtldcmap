## 2. 원인 — 잘못된 계층을 고쳤던 1차 진단의 정정

1차 시도에서 `PORTFOLIO_CONFIG_V132` 에 한글 원천 키를 직접 추가했으나 화면은 변하지 않았다.
실제 차단 지점은 그 앞단인 `REVIEWED_ENTITY_ALIASES_V132` 였다. 이 표가
`normalizedAttributes[sourceKey] → publicKey` 로 **먼저 걸러내므로**, 검토 목록에 없는 키는
config 에 무엇을 적든 조회 시점에 이미 존재하지 않는다. config 에 원천 키를 적는 것은
효과가 없을 뿐 아니라 있지도 않은 매핑이 있는 것처럼 보이게 하므로 되돌렸다.

최종 납품본이 A~D 전 원천의 열 이름을 바꾸면서, 표에 적힌 V1 해시 키
(`field_c7e4ae73`, `commitment`, `dac`, `fy` …)가 더 이상 어떤 레코드에도 걸리지 않았다.

**측정된 범위 — 세 항목의 문제가 아니라 하나의 회귀군:**

| | 별칭 해석 |
|---|---|
| 수정 전 | live 8 / dead 42 (10개 D 항목 전멸, E-008 만 생존) |
| 수정 후 | **live 82 / dead 0** |

## 3. 조치

- `REVIEWED_ENTITY_ALIASES_V132` 를 현재 워크북이 실제로 싣는 열로 재작성.
  열이 스스로 말하는 의미대로 이름을 붙였고, 과거 슬롯 순서로 의미를 추정하지 않았다:
  `기간_시작`→`periodStart`(승인일 아님), `공고일`→`noticeDate`, `제출일`→`submissionDate`,
  `Financial_Close`→`financialCloseDate`.
- D-023 은 GCF·GEF·AF·CTF 가 섞여 있어 날짜 규칙이 기금마다 다르므로 4개 날짜 열을
  하나의 "승인"으로 합치지 않고 분리 유지, 라벨도 일반형(`확인 기간`)으로 둠.
- 금액은 원천이 지정한 숫자열 `대표금액` 을 1순위로 두고, **같은 측정치임을 확인한**
  평문 열만 2순위로 추가. 862건 중복 구간 전수 대조 결과 불일치 0.
  `총_투자액`("50.8 백만 USD")·`계약기간`("20")·`예산`("$200-250k")은 단위·성격이 달라 제외.

## 4. 별도로 확인된 결함 2건

- **D-012 `대표금액` 은 금액이 아니라 용량**: "420MW / 391.0백만 USD" 레코드에서 값이 `420`.
  금액 별칭을 의도적으로 비워 두었다(MW 를 USD 로 공표하지 않기 위함). 원천 정정 필요.
- **D-023 `승인_회계연도` = "1970" 6건**: 원본 워크북 `1.2_entity` 47열에 문자열 '1970' 이
  실제로 존재함(ETL 생성물 아님, openpyxl 직접 확인). GEF 설립은 1991년이므로 상류 export 의
  null 자리표시자다. **원본은 수정하지 않았고 레코드·다운로드도 그대로 둔 채**,
  파생 연도 범위에서만 명시적 `rejectValues` 로 제외(1970–2026 → 1991–2026).
- **`provenance.referenceYear` 대체값 제거**: 날짜가 없는 레코드에 데이터셋 기준연도(2026)를
  넣고 있었다. D-012 의 `확인_연도 = "미상"` 14건이 2026년 진출로 계산되어 범위가
  2019–2026 으로 부풀었다. 원천은 2019–2021 만 말한다. 연도를 말하지 않는 레코드는
  이제 연도에 기여하지 않는다.
