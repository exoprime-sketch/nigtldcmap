# 제공 대상 제외 항목 — V156

프레임워크 152개 요소 중 **10개를 제공 대상에서 제외**한다. 제외는 데이터가 없다는 뜻이 아니라 **제공하지 않기로 한 결정**이며, 판단 근거와 결정일을 함께 기록한다.

- 결정 정본: `config/data-publication/vietnam-exclusions-v156.json`
- 카탈로그 반영: `publicStatus: "excluded"` + `exclusion{reason, basis, decidedAt, measuredStatus, measuredPresence}`
- 공개 요소 수: **152 → 142**

## 데이터·파일 취급

- `public/data/vietnam/v2` 아래의 팩·다운로드 파일은 **삭제하지 않는다**. 결정이 바뀌면 결정 파일에서 해당 줄을 지우고 `npm run refresh:data … --apply`만 다시 돌리면 복귀한다.
- 카탈로그는 제외 전 측정 상태(`measuredStatus`·`measuredPresence`)를 함께 보존한다. "제공하지 않기로 했다"와 "제공할 것이 없다"를 구분해 읽을 수 있어야 하기 때문이다.
- 프레임워크 요소 수(152)와 요소별 계상은 바뀌지 않는다. 게이트의 `FRAMEWORK_ELEMENTS`·`ACCOUNTED_ELEMENTS`는 계속 152다.

## 게이트 기대값 변경(사유 기록)

사유: **사용자 0923 제외 6 + 명세서 0918 제외 4**. 공개 목록을 세는 검사는 숫자를 적지 않고 카탈로그에서 계산한다 — 전체 = `catalog.json` 요소(152), 공개 = `publicStatus ∉ {excluded, not-provided}`(142). 판정 규칙은 바꾸지 않았고, 제외 요소를 대상에서 뺀 감사에는 그 자리에 안내 카드 검사를 넣었다. 검사별 목록은 `reports/v156/EXPECTATION_CHANGES_V156D.md`.
