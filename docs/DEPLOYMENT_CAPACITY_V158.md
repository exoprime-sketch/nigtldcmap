## 2. Vercel 기준 한도 (공식 문서 [Limits](https://vercel.com/docs/limits), 2026-09-16 갱신본)

| 항목 | 한도 | 이 사이트에 해당하는지 |
|---|---|---|
| 빌드 시간 | 배포당 45분 | 해당. 현재 build 약 1분 + 파일 복사 |
| 빌드 디스크 | 32 GB | 해당. 여유가 크다 |

| 업로드 원본 크기·파일 수 | Hobby 100 MB, Pro 1 GB · 15,000개 | **CLI 배포에만 해당**. 이 사이트는 Git 연동 빌드라 해당 없음. `vercel deploy`로 올리면 걸린다 |
| 배포 횟수 | Hobby 하루 100회, 동시 빌드 1 | 해당. 현재 여유 |

  - Vercel 직원 답변([커뮤니티, 2025-01-06](https://community.vercel.com/t/what-is-the-build-size-limit-on-vercel/3859))도 함수 250 MB·빌드 캐시만 언급한다.
  - 실측: 948.7 MB build가 #38 Preview와 #40 production(2026-09-29)에서 모두 성공했다.
- Hobby 월 할당([Fair Use Guidelines](https://vercel.com/docs/limits/fair-use-guidelines), 2026-09-14): Fast Data Transfer 100 GB, Fast Origin Transfer 10 GB.
- **Hobby는 비상업 개인 용도 전용이다.** "사이트를 만들거나 운영하는 대가로 돈을 받는 경우"가 상업 용도의 예로 명시돼 있다. 발주 용역 사이트라면 Pro가 필요할 수 있다(7절 판단 요청).
- 저장소(GitHub): 한 파일 100 MB를 넘으면 push가 거부되고, 50 MB부터 경고한다. 현재 가장 큰 파일은 86.5 MB로 한도에 가깝다.

## 3. 10개국 예측
- 대상국은 `src/data/priorityCountries.ts`의 10개국이다. 이미 측정된 2개국은 실측값을 쓴다.

## 5. 권고안 — 요소별 다운로드 사전 압축 (Vercel 단일 원본)
- **바꾸는 것**(채택 2026-09-30, 구현은 별도 PR)
  - ETL이 `downloads/<요소>.zip`(그 요소의 CSV·JSON)을 쓴다.
    - 결정적 ZIP이다: 고정 시각, 정렬된 항목, 레벨 9. 같은 입력이면 같은 해시가 나온다.
  - 카탈로그 `downloadAssets[].url`이 `.zip`을 가리키고, 안의 파일 목록과 해시를 싣는다. `asset-integrity`도 갱신한다.
  - 감사 조정: 보안 감사의 다운로드 필드 검사를 ZIP 안 파일로, 전달 매니페스트 검사도 맞춘다.
    - 기대값 변경은 사유를 기록한다.
- **바뀌지 않는 것**
  - 화면: 다운로드 화면은 팩에서 파일을 만들므로 변화 0이다. 확인 결과 `src`에서 정적 다운로드 파일을 부르는 곳이 0이다.
  - 팩·경계·공간 자산
- **효과**
  - 배포 1회: 948.7 MB → 약 164 MB(현재 2개국)
  - 10개국: 최대 1.19 GB
  - 가장 큰 파일은 3.8 MB가 된다.

## 8. 구현 결과 (V158-ZIP, 2026-09-30)
- ETL(베트남 `tools/etl/build_public_v2.py`, 방글라데시 `tools/etl/countries/bgd/build_country_v2.py`)이 요소별 `downloads/<id>.zip`을 쓴다. 안의 JSON·CSV는 전환 전 파일과 같은 방식으로 만들고, 카탈로그 `downloadAssets`는 ZIP 1개와 안쪽 파일 목록·크기·해시를 싣는다. 결정적 ZIP이다(`tools/etl/download_zip_v158.py`: 이름순, 1980-01-01 시각, 고정 파일 모드, 레벨 9).
- 베트남은 `refresh:data`를 지난 갱신과 같은 인자로 다시 돌렸다. 값 비교 결과 152요소 모두 변화 0(값 변경·관측 증감 0)이다. ZIP 147개의 안쪽 CSV는 전환 전 파일과 바이트 단위로 같고, JSON은 요소 행의 `downloadAssets`만 다르다.
- 5절 정정: 팩은 요소 행의 복사본(`meta.element`)에 `downloadAssets`를 싣기 때문에 팩 해시가 바뀐다. 레코드는 바뀌지 않았다.
- 배포 용량(production 빌드 실측, `reports/v158/download-zip-size-v158.md`)

| 항목 | 전 | 후 |
|---|---|---|
| 배포 전체 | 948.7 MB · 867개 | 164.4 MB · 635개 |
| 베트남 다운로드 | 662.3 MB · 294개 | 19.0 MB · 147개 |
| 방글라데시 다운로드 | 145.3 MB · 170개 | 4.4 MB · 85개 |
| 가장 큰 파일 | 86.5 MB(b-006.json) | 12.3 MB(지도 경계 GeoJSON) |

- 기존 주소 `downloads/<id>.json·csv`는 404다(7절 2 결정). CRA 프리셋이 없는 경로를 index.html로 돌려주므로, `vercel.json`에 `routes`(파일시스템 확인 → 없는 `/data/**` 404)를 넣었다. `ignoreCommand`와 리다이렉트는 없다.
